# 高级配置与排障说明（`ocr` 段）

> 面向对象：在**非标准系统缩放**（如 125% / 150% / 175%）下识别异常、愿意手动微调的使用者。
> 识别引擎为 **PaddleOCR PP-OCRv5 mobile**（本地模型，随程序分发）。
> 默认**无需改动**：本应用已按 `dpi/96` 自动归一化，100% / 125% / 150% 实测通过。

## 1. `config.json` 中的 `ocr` 段

```json
"ocr": {
  "baseRegion": { "x": 300, "y": 33, "width": 580, "height": 30 },
  "baseScale": 2,
  "normalizeByDpi": true,
  "dumpDirectory": ""
}
```

| 字段 | 含义 |
|------|------|
| `baseRegion` | **96 DPI 基准**下，从「渲染子窗口客户区」左上角起的裁剪区（即标题所在的那一条）。`x/y/width/height` 均为 96 DPI 逻辑像素，不是整个微信窗口的坐标 |
| `baseScale` | 裁剪图放大倍数；放大后再送入 OCR。`2` 表示放大 2 倍（PaddleOCR 的实测甜区为 2~3，`1` 会完全识别不出） |
| `normalizeByDpi` | 是否按 `dpi/96` 归一化。实现为：裁剪区 × `(dpi/96)` 后在物理图上裁剪 → 再把裁剪图**缩回 96 DPI 基准尺寸** → 最后按**整数** `baseScale` 放大。**请保持 `true`** |
| `dumpDirectory` | 填目录后，每次识别的裁剪图会落盘，用于排障；留空则不落盘 |

## 2. 先分清是「没识别到」还是「识别错了」

打开主窗口，看 **识别文本** 一栏：

- 一直为 `—` / 空 → 多半是窗口层或 DPI 层问题（可先看「微信窗口 / 渲染区 / DPI」三栏）；
- 有字但不对（缺字、错字）→ 走第 3 步，微调裁剪区与放大倍数。

## 3. 微调步骤

1. 把 `dumpDirectory` 设为某个空目录（例如 `"E:\\wsg-dump"`），保存后：**托盘右键 → 重载配置**。
2. 保持微信在前台并停留在目标聊天上，稍等片刻即会落盘出图；打开最新一组的 `…-raw.png`（当前为单路识别，仅产出 raw 一路）。
3. 对照图片判断：

   | 现象 | 调整 |
   |------|------|
   | 标题被上下切掉 | 调 `baseRegion.height`（必要时同时调 `y`） |
   | 图里混进了标题下方的其他行 / 元素 | 调**小** `baseRegion.height` |
   | 字太小或发虚 | 调**大** `baseScale`（如 `2` → `3`；再大收益递减且更慢） |
   | 日志「识别参数」里**缩回基准**的宽/高**小于** `baseRegion` | 发生了**裁边**（裁剪区超出渲染区），标题右端/下端可能被切；适当减小 `width`/`height`，或调整 `x`/`y` |

4. 改完保存 → 托盘「重载配置」→ 再看主窗口「识别文本」是否与标题一致。
5. 调到满意后，把 `dumpDirectory` 复位为 `""`。

## 4. 注意事项

- 本应用**不读取微信进程**，只做屏幕识别；标题被其他窗口遮挡、或聊天列表在滚动时，识别可能失败，属正常现象。
- 裁剪区**超出渲染区时会自动裁边**：例如渲染区宽 873 而 `baseRegion` 右边界到 880，实际只裁到 873。若日志「识别参数」中"缩回基准"的宽/高小于 `baseRegion`，即为发生了裁边，标题右端/下端可能被切。
- 识别失败时**不会给出「安全」提示**（按需求 FR-09 失败策略处理，宁可提示"无法确认"也不误报安全）。
- `baseRegion` 以「渲染子窗口客户区」为原点。主窗口「渲染区」一栏显示该区域的实际物理矩形，可用于对照。
